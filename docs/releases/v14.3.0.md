# Shardelix 14.3.0 — real physical document strips, pixel-only

This update focuses on the three **real physical scans** of DocDataset.
The solver still consumes only rectified scan pixels and foreground masks.
No OCR, language model, trained model, intact page, filename ordering, or
ground-truth ordering enters inference.

## Algorithm

- Preserve the previous column/local shadow correction and vertical
  registration, and the coarse stroke + patch continuation cost.
- Extract the patch recurrence and hypothesis selection into a small
  geometry-specific module, `strips/document_patches.py`.
- Test two explicit missing-cut widths (2 and 3 pixels at the matching
  resolution). Sample observed half-patch centers at their physical offsets
  from each seam and increase vertical sampling density. Compare two-way
  continuations using a bounded same-page interior patch index.
- Evaluate each calibrated cost at three mixture weights with the coarse
  cost. Select from at most seven directed chains (including the coarse
  baseline) using the mean reciprocal edge rank minus half the normalized
  signed alternative-edge margin. The selection score is a heuristic, not
  an accuracy probability. No evaluation labels enter this choice.
- Refine only the selected chain with the existing bounded global optimizer.
  Keep exported observed pixels and the existing geometry/output contract.
- Activate the new bank for high-resolution scans (at least eight strips,
  normalized height >= 1500 px, minimum width >= 20 px); the fixed pixel-gap
  range is not scale invariant. Existing smaller/fast/color and irregular
  routes retain their previous algorithms.

## Real physical scan benchmark (Balanced, native CPU)

| Case | V14.2 directed joins | V14.3 directed joins | V14.2 exact positions | V14.3 exact positions |
|---|---:|---:|---:|---:|
| real1_27 | 20/26 | 26/26 | 14/27 | 27/27 |
| real2_56 | 55/55 | 55/55 | 56/56 | 56/56 |
| real3_39 | 34/38 | 38/38 | 22/39 | 39/39 |
| **Total** | **109/119 (91.6%)** | **119/119 (100%)** | **92/122 (75.4%)** | **122/122 (100%)** |

Both filename anonymization seeds (624 and 2026) reproduce all exact orders
in Balanced. A separate High accuracy run (seed 624) also reaches 119/119
directed joins and 122/122 positions.
The chosen mixture can differ between permutations. The scans and supplied
foreground masks are unchanged; answer ordering is read only after
reconstruction. Each run is a full solve, not reuse of a solved chain.

The three cases were used in development, so this is **not held-out validation**
or a SOTA claim. Accuracy on different real scans, more severe cut damage
and unknown global orientation is not guaranteed. Perfect order is not
proof of perfect subpixel alignment. Added patch searches increase CPU time;
no browser speed or synthetic-stress gain is claimed.

## Reproduce

```bash
PYTHONPATH=src python benchmarks/benchmark_scanned_strips.py DocDataset.zip --seed 624 --out real624.json
PYTHONPATH=src python benchmarks/benchmark_scanned_strips.py DocDataset.zip --seed 2026 --out real2026.json
PYTHONPATH=src python benchmarks/benchmark_scanned_strips.py DocDataset.zip --profile accurate --seed 624 --out accurate624.json
```

The [paired measurements](../../reports/v14/scan_document_v143.json) contain
per-case runtimes, matching diagnostics and selected hypotheses. Original
scans, ordering labels and page images are not distributed with the repo.
